# Trend sources

The pinned list `trend-radar` reads. Pinned on purpose: an open-ended "what's new in UX" search
returns the same recycled listicles every week, and the report is only as good as this file.

Curate it. Drop sources that never produce anything that clears the bar.

## The two bars

An item only makes the report if it clears **both**:

1. **It names a specific technique or pattern.** Not "AI is changing design." A named interaction,
   a named layout approach, a named implementation trick, with enough detail to build from.
2. **It maps to a named surface in one of my products.** From the *surfaces I own* list in
   `PROFILE.md`, or a named screen in a product I work on.

Items clearing one bar but not the other are dropped, **not padded into the report**. A three-item
report is a good week. A zero-item report is an honest week, and the right output is one line
saying so.

## Output format

Always the same three parts:

> **<trend>** — <the specific technique, one or two sentences>
> **Where it lands:** <the actual screen or component it would change>
> **What it'd take:** <the work, honestly — including "probably not worth it">

## Recurrence

`reviews/trends.md` accumulates every item ever reported. Something appearing three weeks running
from different sources is a much stronger signal than something appearing once, and the report
should say when that happens.
